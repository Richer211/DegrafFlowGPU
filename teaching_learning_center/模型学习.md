# 模型学习（本项目课记）

配套：`raft.py`、`extractor.py`、`corr.py`、`update.py`、`export_raft_onnx.py`、`run_gpu_pipeline.sh`  
PyTorch 语法细节见：`Pytorch.md`；部署见：`TensorRT.md`

---

## 1. 三个东西：PyTorch / ONNX / TensorRT

本项目光流链：

```text
raft.py（结构）+ .pth（权重）
    → torch.onnx.export → .onnx
    → TensorRT 编译 → .engine
    → C++（RaftEngineTRT）加载推理
```

| | 是什么 | 本项目 |
|---|---|---|
| **PyTorch** | 写结构、训练、导出的工具 | `raft.py`、导出脚本 |
| **ONNX** | 冻好的通用计算图 | 中间文件 |
| **TensorRT `.engine`** | 针对某张 GPU 编好的可执行体 | `raft_*.engine`；给人几乎不可读 |

`run_gpu_pipeline.sh` 读的是 **`.engine`**，不是 `.py`。  
只改 `raft.py` 不重新导出+编译 → **engine 不会变**。

## 2. 「模型」到底是什么？

一句话：**规定好的输入→输出映射 = 结构（层怎么连）+ 前向算法（`forward`）+ 权重（学到的数）。**

- 给你图像对，吐出光流 → RAFT 就是这样一个完整东西。  
- 模型**不是**宇宙唯一公式；换结构/权重就是另一个模型。  
- PyTorch 是实现它的工具；**模型本身 ≠ PyTorch**。

**会写模型 ≠ 只会调 API**：要清楚数据流、形状、训练/推理差别、问题出在哪一层。

---

## 3. 训练 vs 推理

| | 有什么 | 在干什么 |
|---|---|---|
| **结构** | 卷积、BN、Dropout、`forward` 连法 | 规定数怎么流 |
| **训练** | 结构 + **损失** + **梯度/反向传播** + **优化器** + **带标注数据** | 反复改参数，让输出靠近真值 |
| **权重** | 训练后留下的参数（`.pth`） | 不是「梯度本身」；是被梯度更新很多轮后的数 |
| **推理** | 结构 + 固定权重 + `forward`（常 `eval`+`no_grad`） | 输入→相对稳定的输出 |

**我曾混的点**

- 梯度：指示「权重往哪拧」；拧完留下的叫权重。  
- 训练需要的是带答案的数据，不只是「随便测几张图」。

## 4. RAFT 在本项目里怎么跑（`forward`）

文件：`external/RAFT/core/raft.py`

### 4.1 正确流程（纠正版）

1. 预处理：像素收到约 `-1~1`；`contiguous()`  
2. **`fnet` 各跑一次**：两帧 → `fmap1, fmap2`（`extractor.py`）  
3. 建 **`CorrBlock`**（`corr.py`）：后面按坐标查「有多像」  
4. **`cnet` 对 image1 跑一次**：拆成 `net` + `inp`  
5. 初始化 `coords0, coords1`；**光流 = `coords1 - coords0`**  
6. **循环多轮**（不是每轮重跑 fnet/cnet）：  
   - 查 `corr`  
   - `update_block` → `delta_flow`（并更新 `net`）  
   - `coords1 += delta_flow`  
   - **上采样**得到更细的光流，记入列表  
7. 返回（`test_mode` 时常给低分辨率流 + 上采样流）

**我曾错的点**

- 循环里主要不是「更新精度」；精度由 `autocast` 开关管。  
- 循环里是：相关 → 更新 → 改坐标 → 上采样。

### 4.2 零件分别干什么

| 零件 | 干什么 |
|---|---|
| **fnet** | 两帧都提特征 → 给相关用 |
| **cnet** | 主要看第一帧 → 上下文 + 隐藏状态 |
| **corr** | 回答「按当前坐标，两图局部有多像」 |
| **update_block** | 决策器：看 corr、当前 flow、记忆 → 输出 **`delta_flow`**，并更新 `net` |
| **delta_flow** | 本轮对坐标的**修正量**；多轮累加才逼近好光流 |
| **net** | 跨轮**隐藏状态/记忆**；每轮被 update 改写（精神上像「带着上轮信息」，不要硬等同 Transformer 残差） |
| **inp** | 上下文特征图（张量，约 `N×cdim×H/8×W/8`），当「参考说明书」，不是 RGB 照片 |

**「上下文」在这里指什么？**  
不是聊天上下文，而是从第一帧提出来的、描述场景的特征，帮助决定怎么改光流。

### 4.3 低分辨率 vs 上采样

| | 目的 |
|---|---|
| 先在约 **1/8** 分辨率上迭代 | 格子少、算得起；先抓大位移 |
| **上采样** | 拉回接近原图大小，才稠密、好用 |

### 4.4 为啥要 fnet + cnet 两套？

- fnet：对齐两帧（相关）  
- cnet：服务迭代更新（记忆 + 上下文）  
不是简单重复。

## 5. 怎么学会「自己写模型」？

### 5.1 三档能力（别混）

| 档 | 你会什么 | 多数岗位 |
|---|---|---|
| **A 会用会改** | 跑通、微调、导出、查数据/指标/延迟 | 很常见 |
| **B 会复现实现** | 对着论文/开源用 PyTorch 写出类似 RAFT 的结构并跑通 | 扎实中高级 |
| **C 会发明** | 新结构/新方法并证明更好 | 研究向、少数人 |

长期壁垒常在：问题定义、数据、指标、系统稳定性；不只是「谁画出新网络草图」。  
JD 很少要求「必须设计全新 SOTA」；更常见 A + 一点 B。  
**从零发明架构 ≈ 论文/博士训练常见贡献；工程师大量价值在 A/B + 落地。**

### 5.2 推荐顺序（已定）

1. **A**：会读、会跑、会改现有模型（当前）  
2. **B**：自己写小模型 / 复现一块  
3. **C**：有需要再碰创新  

务实练习：小 `nn.Module` → 画清 RAFT 方框 → 改一处看形状 → 对照半篇论文 → 可选跑通最小训练环。

### 5.3 诚实面试口径（本项目）

「模型结构来自开源 RAFT；我参与的是理解数据流、导出/TensorRT 部署链、RealSense 数据与可视化/报警，不是从零设计 RAFT。」  
不夸大、不掉价。

## 6. 多模态（求职高频词）

**模态**：图像、文本、语音、深度、点云…  
**多模态模型/算法**：同一系统里联合 **两种以上** 模态。

| 单模态（本项目偏此） | 招聘常说的多模态 |
|---|---|
| RGB（+深度几何）→ 光流/场景流 | 常指 **视觉↔语言** 等（VLM、图文检索） |
| RAFT | CLIP / 看图问答 /「按一句话找目标」 |

RGB+Depth 是多传感器，但 JD 里「多模态」多数不是单指 RGB-D。

高薪岗爱写它：产品要「能听懂语言的视觉」、热度在 VLM；要的常常是 **会用/微调/接入**，不是从零设计 GPT-4V。  
传送带主线仍可先做运动几何；以后「找出那箱药」才可能接语言层。

## 7. 和大模型/小模型

粗分：参数量、算力、能力与成本不同。  
RAFT 相对 LLM 是 **小而专的视觉模型**；小的也是完整模型。

## 9. 自测

1. 跑 `seq_box_slide` 光流时，程序主要读 `.py` 还是 `.engine`？  
2. `fnet`/`cnet` 是每轮都重跑，还是大体各一次？循环更新什么？  
3. `delta_flow` 和 `flow=coords1-coords0` 关系？  
4. 权重和梯度差在哪？  
5. 多模态和「只用 RGB 做光流」差在哪？举一个产线例子。

**短答**  
1. `.engine`  
2. 大体各一次；相关→delta→坐标→上采样  
3. delta 是每轮修正；累加后坐标差才是当前光流  
4. 梯度指示更新方向；权重是更新后的参数  
5. 多模态再融合文本等；例：语音/文字指定「扫异常的红盒」
